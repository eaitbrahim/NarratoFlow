# Plan 5: Render Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** For each part that Plan 4 built (`part-NN.flac` + `part-NN.timeline.json`), produce `part-NN.mp4` (1080x1920, 30 fps, H.264 + AAC) and `part-NN.render.json`:
- a drawing hand reveals each sketch stroke by stroke, on the exact `draw_schedule` the audio used, with a virtual camera following the pen inside the stage zone;
- each appearance of a sketch gets free, deterministic variations;
- Arabic and English captions are timed to the narration words;
- verses are font-rendered exactly from the corpus and revealed word by word, right to left, on the recitation timing;
- the hook, "Part N of M", the recap and the teaser are on screen, inside pinned safe zones.

**Architecture:**
- **Two layers.**
  - *Pixels* (the sketch, the text-card frame, the hand, the camera) are composited in numpy/PIL per scene. Each scene is piped as rawvideo into its own lossless FFV1 segment, and scenes run in parallel in a spawn process pool.
  - *All text* (captions, verse, overlays, card text) is one `.ass` file per part. libass (HarfBuzz + FriBiDi) shapes it in a single final ffmpeg pass. That pass concatenates the segments, burns the ASS, muxes the part FLAC and encodes H.264.
- **No reshaper, no Python text shaping.** Text stays logical-order Unicode from the timeline and the corpus to libass.
- **Refuse before rendering.** A timeline that no longer matches the series, the library or the corpus is refused before any frame is rendered.
- **Orchestration** is `render/build.py`. The CLI adds `narratoflow render`.

**Tech Stack:** Python 3.12, numpy, Pillow, opencv-python-headless (already deps), the ffmpeg/ffprobe CLI built with libass, libx264 and ffv1, and **one new core dependency, `fonttools`** (MIT), used to verify the bundled fonts' family names and glyph coverage. The fonts are OFL-1.1 (Amiri, Amiri Quran, Noto Sans). The hand sprite is NarratoFlow's own work, generated by a script.

**Spec:** `docs/superpowers/specs/2026-11-10-sketch-library-pipeline-design.md`. This plan implements:
- §3 step 6;
- §4.4 (the marker re-render at render time);
- §4.5 (free variations);
- §2.2b and §2.2d (on-screen hook, Part N of M, recap and teaser, never spoken; the hook at 0 s);
- §2.2c (the drawing-hand sprite is the only body part added);
- §2.2e (the verse font-rendered exactly, word by word RTL, whole-ayah fallback);

- the render facts §5.3 and §6.2–6.3 need (variation applied, font and hand provenance, the verse exact-text result), recorded in `part-NN.render.json` for Plan 6.

## Global Constraints

- **The Plan 4 contract is consumed exactly** (`audio/timeline.py` module doc, `visuals/schedule.py`):
  - The stroke reveal is `draw_schedule(strokes, draw_start_ms, draw_end_ms)`, recomputed from the scene's current library strokes in their **stored order**. `SfxHit.stroke_index` indexes that order.
  - Zero-length stroke events and zero-length or overlapping words are valid input. Only word *starts* are non-decreasing.
  - A drawn scene whose `sketch_id` or `stroke_count` differs from the library (or is None) raises `StaleTimelineError("... rebuild audio: narratoflow audio build ...")`.
  - `integrated_lufs` and `true_peak_dbtp` may be None. They are copied into the report, never formatted as numbers without a None check.
- **v1 is 9:16 only [spec §8].** `FRAME = 1080x1920`, `FPS = 30` (exactly 30/1, constant frame rate).
  - A channel whose `outputs` contains `16:9` renders 9:16 only and gets the report warning `"16:9 is not rendered in v1"`.
  - `Scene.layouts` is ignored in v1.
- **Pinned safe zones at 1080x1920** (`render/layout.py`; a `Rect` is x, y, w, h in px):
  - Unsafe areas: `PLATFORM_TOP = Rect(0, 0, 1080, 160)`, `RIGHT_RAIL = Rect(888, 768, 192, 1152)`, `PLATFORM_BOTTOM = Rect(0, 1440, 1080, 480)`, plus `LEFT_MARGIN = Rect(0, 0, 60, 1920)`, the seventh rect. No content zone intersects it.
  - Content zones: `TOP_BAR = Rect(60, 170, 960, 200)`, `STAGE = Rect(60, 390, 828, 850)`, `CAPTIONS = Rect(60, 1260, 828, 180)`.
  - How these were derived: TikTok (≈130 px top, 150 px right rail, 480 px bottom) and YouTube Shorts (192 px right rail; its 288 px top and 672 px bottom figures are ad-placement guidance). Where the two platforms disagree, the larger figure wins, except at the top and bottom, where the owner's §8 bands (top bar below ≈8 %, captions at 65–78 %) govern.
  - **No sketch pixel, hand pixel or text ink may land outside its zone.**
- **Nothing is spoken here.** Render reads audio. It never calls a voice, an LLM or the network, and it spends nothing.
  - It still refuses an unapproved series (`PlanningError("approve the series first")`) and runs `require_series_channel`.
- **Verses [spec §2.2e, §6.3].**
  - The on-screen text is `corpus.ayah(s, a).uthmani`. It is never the pasted text, never `VerseRef.uthmani_text`, never strokes.
  - The text is cut into display words with `audio.recitation.display_words`.
  - A timeline ayah list or word texts that differ from the corpus raises `RenderError("FAIL: verse <s:a> ...")`. So does a codepoint missing from the verse font's cmap. Both are raised before encoding, and there is no override.
- **Fonts and the hand are bundled assets with provenance [spec §6.2].**
  - Every file is listed in its `index.toml` with `license`, `source` and `sha256` (fonts also need `license_file`), and in `assets/LICENSES.md`.
  - Allowed licences: fonts `OFL-1.1`; the hand `Apache-2.0`/`CC0-1.0`/`MIT`/`ISC`/`CC-BY-4.0` (with attribution).
  - Fonts are supplied to libass only through `fontsdir=` from a copy of the bundled fonts. libass in ffmpeg may still enable a system fallback provider, so glyph coverage is enforced by `missing_glyphs`, not by fontconfig. A caption glyph the font lacks adds the report warning `"<scene>: caption glyphs missing from <font>: U+XXXX..."`.
- **ffmpeg for render must have libass.**
  - `find_render_tools(settings)` uses `Settings.ffmpeg` (`NARRATOFLOW_FFMPEG`), else `shutil.which("ffmpeg")`, and `ffprobe` beside it, else on PATH.
  - It requires the `ass` filter and the `libx264`, `ffv1` and `aac` encoders. When the `ass` filter is missing, the message names the macOS fix (`brew install ffmpeg-full` and set `NARRATOFLOW_FFMPEG=$(brew --prefix ffmpeg-full)/bin/ffmpeg`). Homebrew's default `ffmpeg` 8.x has no libass, as checked on the owner's machine.
  - Audio keeps `audio.io.require_ffmpeg` unchanged.
- **Determinism [spec §4.5].**
  - `video_id(series) = f"{series.channel_slug}/{series.title}"` is ONE function in `visuals/marker.py` beside `marker_seed`. `audio/build.py` and `sketching/generate.py` call it (Task 4 moves it), and render imports it. `wobble_seed = marker_seed(video_id(series), scene.id)`.
  - Variation draws come from `np.random.default_rng([wobble_seed, 1])` in a fixed order.
  - Re-rendering gives identical decoded frames (checked with ffmpeg `framemd5`). The worker count never changes the output.
- `subprocess` is called with an argument list, an absolute tool path and a timeout, never `shell=True`. A non-zero exit raises `RenderError` with the last 5 stderr lines. Filtergraph paths are never interpolated: the final pass runs with `cwd=<work dir>` and uses the relative names `captions.ass` and `fonts`.
- New errors (Task 1): `RenderError(NarratoFlowError)` and `StaleTimelineError(RenderError)`.
- **Tests never touch the network.**
  - Pipeline tests render at `Canvas(scale=Fraction(1, 6))` (180x320) with timelines of ≤ 4 s. libass checks render single 1080x1920 stills.
  - Tests needing libass use the `render_tools` fixture. It skips locally when ffmpeg lacks libass and **fails** when `CI` is set. The autouse `_isolate_env` in `tests/conftest.py` deletes every `NARRATOFLOW_*` variable, so the fixture reads `NARRATOFLOW_FFMPEG` at module import time of `tests/render/conftest.py` (before any fixture runs) and passes it explicitly. The owner can then run libass tests locally with `ffmpeg-full`.
  - Verse tests use the `tests/fixtures/quran/` corpus (31:33 is in it).
- Same tooling gate as Plans 1–4 (ruff check, ruff format --check, mypy strict on src and tests, pytest under branch coverage). Sources are pure ASCII with `\u` escapes, so Arabic test strings are written as escapes, e.g. `"سسس"`.

## Review Focus

1. **Arabic shaped wrongly or in the wrong order.** Causes: a libass built without HarfBuzz (letters drawn isolated), an LTR base direction (a trailing `.` or `؟` on the right), or a fill sweep running left to right over RTL words. Expected:
   - preflight's shaping self-test refuses such an ffmpeg with the `ffmpeg-full` hint;
   - Arabic styles use `Encoding = -1` (auto base direction), so trailing punctuation sits left of the word;
   - captions and verses use `\k` (an instant switch), never `\kf`, and the first word revealed is the rightmost.

   → Task 1 and Task 7 tests.
2. **The verse on screen is not exactly the corpus.** Causes: a timeline written from an older corpus, a hand-edited timeline, or a verse font missing one Uthmani mark (libass would silently fall back to a system font). Expected: `RenderError("FAIL: ...")` before any segment is encoded; the text the ASS shows, with tags stripped and pages joined, equals `" ".join(uthmani.split())`. → Task 8 tests.
3. **The timeline is stale.** Causes: `sketch resolve` swapped the sketch, a scene became a text card, scenes were re-planned, or the FLAC was rebuilt without its timeline. Expected: `StaleTimelineError` naming the scene and "rebuild audio", before any frame is rendered. → Task 10 tests.
4. **Content in unsafe zones.** Cases: the hand near the stage's right or bottom edge, a two-line caption page, a 10-word verse page of 31:33, a 60-character hook. Expected: compositor pixels outside `STAGE` stay paper on every frame, and each libass still has its ink inside its own zone. → Task 6, Task 7 and Task 8 tests.
5. **Audio/video drift over a long part.** Cases: many scenes with boundaries off the 33.3 ms grid, or a 90 s part. Expected:
   - segment frame counts sum exactly to `frame_of(duration_ms)`;
   - ffprobe shows `nb_frames` equal to that sum;
   - the video and audio durations differ by ≤ `AV_TOLERANCE_MS = 50`.

   → Task 1 and Task 9 tests.

- Font index entry: `[fonts.<id>] file, family, license = "OFL-1.1", license_file, source, sha256`. These fields are exactly the required set.
- `@dataclass(frozen=True) class FontAsset: id: str; file: Path; family: str; license: str; license_file: Path; source: str; sha256: str`
- `FontPack.from_index(path: Path) -> FontPack` validates in the manner of `SfxPack.from_index`:
  - `confined_file(..., ".ttf")` for `file`, and `confined_file(..., ".txt")` for `license_file`;
  - the licence must be `OFL-1.1`;
  - the sha256 of the file must match;
  - the family must be the font's name-table ID 16 if present, else ID 1 (fontTools `TTFont(file)["name"]`);
  - any violation raises `ChannelConfigError` naming the entry.
- `FontPack` methods: `get(id) -> FontAsset`; `ids() -> list[str]`; `copy_to(dir: Path) -> None` (copies the font files only); `missing_glyphs(id: str, text: str) -> list[str]` (`"U+XXXX"`, sorted, unique). The check skips whitespace and category `Cf`, and caches the cmap per font.
- `default_fonts() -> FontPack`, the hand counterpart `default_hand() -> HandSprite`: the packaged location first, then the dev checkout. Unlike icons, a missing index raises `ChannelConfigError("bundled fonts not found ...")`, because render cannot run without them.
- `@dataclass(frozen=True) class HandSprite: id: str; file: Path; license: str; source: str; attribution: str; tip: tuple[int, int]; sha256: str`.
  - `HandSprite.from_index(path)` reads `[hands.right]` with the fields `file` (`.png`), `license`, `source`, `tip_x`, `tip_y`, `sha256` and an optional `attribution`. The licence allow-list is `audio.sfx.ASSET_LICENSES`, and `CC-BY-4.0` needs an attribution.
  - The file's sha256 must match the index entry (verified like fonts, spec §6.2). The PNG must be RGBA and its tip pixel must lie inside the image with alpha > 0.
  - `HandSprite.image(scale: Fraction) -> tuple[np.ndarray, tuple[int, int]]` returns the RGBA array resized with `cv2.INTER_AREA` and the scaled tip. The cache is a module-level `functools.lru_cache` over a helper keyed on `(file, sha256, scale)`, so `HandSprite` stays plain picklable frozen data with no cache field (it travels inside every `SceneJob`).
- `scripts/make_hand.py`:

  - it prints the tip coordinates;
  - it has no randomness;
  - its output is NarratoFlow's own work, under `Apache-2.0`, with source `scripts/make_hand.py`.

- `narratoflow render SERIES_JSON --channel PATH [--part N]... [--audio DIR] [--out DIR] [--workers N]`:
  - `--audio` defaults to `SERIES_JSON.parent / "audio"`;
  - `--out` defaults to the audio directory, so the MP4 sits next to its FLAC and timeline;
  - `--workers` defaults to None (the CPU count);
  - it runs `build_render`; errors exit 1 through `main()`.
- Output, one line per part: `part N/M: <s> s, <frames> frames, 1080x1920 @ 30 fps -> <mp4>`, then `  report: <json>`, then one `[yellow]warning:[/yellow] part N: ...` line per report warning.
